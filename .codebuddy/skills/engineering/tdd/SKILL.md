# 测试驱动开发（Go）

## 理念

**测试验证行为，不验证实现。** 测试通过公共接口执行真实代码路径，描述系统*做什么*而非*怎么做*。重构后不应有测试失败——如果重命名内部函数导致测试挂了，测的是实现不是行为。

**好的测试**：通过 `FetchProfile` / `handleProxy` / MCP 工具入口等公共 API 走真实路径。坏的测试：mock 内部协作者、测私有方法、绕过接口直查落盘文件。

## 反模式：水平切片

**不要先写所有测试再写所有实现。** 批量写出的测试测的是想象的行为，对真实变化不敏感。

正确做法是垂直切片（tracer bullet）：一个测试 → 一个实现 → 重复。

```
错误（水平）：RED: test1..test5 → GREEN: impl1..impl5
正确（垂直）：RED→GREEN: test1→impl1，test2→impl2，...
```

## 工作流

### 1. 规划（写码前）

- [ ] 与用户确认公共接口形态（core 包函数签名 / MCP 工具出入参）
- [ ] 确认要测试的行为并排优先级（不可能全测，聚焦关键路径）
- [ ] 列出要测的**行为清单**（不是实现步骤）

### 2. 示踪弹

```
RED:   写第一个行为测试（如：fetch http 失败返回带目标地址的错误）→ 失败
GREEN: 最少代码让它通过 → 通过
```

证明路径端到端工作后再继续。

### 3. 增量循环

每个剩余行为：`RED（写下一个测试）→ GREEN（最少代码通过）`。

规则：一次一个测试；只写足够通过当前测试的代码；不预期未来测试。

### 4. 重构

全绿后再重构：提取重复、加深模块。**RED 状态绝不重构**，先到 GREEN。

## Go 惯例（本项目）

- 表驱动测试：`tests := []struct{ name string; ... }{...}` + `t.Run`
- HTTP 层用 `httptest.NewServer` 起真实目标（模拟被采集服务的 `/debug/pprof/*`），不起 mock interface
- 白名单/SSRF 防护逻辑必须有独立用例：非白名单路径、伪造路径（`/debug/pprof/../../etc/passwd`）必须被拒
- 临时落盘用 `t.TempDir()`，不污染默认 `/tmp/pprof-web`

## 每轮检查清单

```
[ ] 测试描述行为，只使用公共接口
[ ] 测试能在内部重构后存活
[ ] 代码对当前测试是最少的，无推测性功能
```
